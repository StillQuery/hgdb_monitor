# hgdb_monitor

`hgdb_monitor` 是一个面向 **HGDB / PostgreSQL** 的只读监控插件。

旨在提供一套轻便的监控系统。它将数据库当下的状态和最近两小时的变化摊开，同时允许 AI 能在对话里查到同样的信息，即定位“现在谁在阻塞”“刚才是不是变慢了”这类问题时，不用切出 Harness。

## 功能

监控能力分五层，从上往下依次收窄：

**① 实例层 · 实时总览**
主备角色、连接使用（总会话 / 活跃 / 等待 / 阻塞 / 空闲事务）、事务速率、缓存命中率、复制延迟、未授予锁、最大连接数。

**② 会话层 · 谁在干什么**
活跃会话、等待会话、长查询、长事务、长时间空闲事务，以及**阻塞链**——谁挡住了谁、锁在什么对象上、被阻塞方的 SQL 长什么样。

**③ SQL 层 · 慢在哪**
Top SQL 排行，可按总耗时、平均耗时、调用次数、返回行数四种口径排序；以及 EXPLAIN 执行计划预估——**只生成计划、不执行语句**。

**④ 复制层 · 下游跟得上吗**
主备身份、下游复制连接、复制槽占用与延迟。

**⑤ 时间层 · 最近两小时怎么变的**
开启持续采集后每 15 秒采样一次，保留最近 2 小时并画出趋势曲线；诊断时可以把当前窗口与**前一个等长窗口**对比，回答“比之前慢了吗”。

## 使用流程

在监控总览的实例标题左侧，可上下拨动半齿轮、点击上半区或下半区，或在齿轮聚焦时按上下方向键切换实例。拨到「＋」档时，当前监控不变，点击实例名下方的「添加数据源」才会打开表单。从总览新增时，保存后切到新实例，测试连接成功后显示实时指标；从「管理数据源」新增时，保存后留在管理页，可在列表中测试、编辑、删除或开启持续采集。

```
        ① 配置数据源
   主机 / 端口 / 库名 / 用户 / 密码 / SSL 模式 / 超时
                    │
                    ▼
        ② 测试连接（只读会话）
     校验连通性、认证、权限、版本能力
                    │
          ┌─────────┴─────────┐
       成功                 失败
          │                   │
          ▼                   └──→ 修正配置重试
   ③ 加入实例列表（最多 5 个）
          │
          ├──→ ④ 打开监控总览：实时看实例 / 会话 / 阻塞
          │
          ├──→ ⑤ 按需开启持续采集：积累 2 小时趋势
          │
          └──→ ⑥ 在 AI 面板直接提问：
               “数据库正常吗”“为什么变慢了”
               → 助手自动调用工具取数并给出结论
```

## 使用限制

- **仅支持 HGDB 及 PostgreSQL 14+ 的PG系数据库**。
- **最多 5 个数据源**；单次明细查询（会话、阻塞、Top SQL、下游连接）最多返回 20 条。
- **历史趋势需要手动开启持续采集**，最长保留 2 小时，超出部分自动丢弃；未开启时只能看实时快照。
- **Top SQL 依赖 `pg_stat_statements` 扩展**，实例未启用该扩展时该模块为空。
- **需要足够的只读权限**（如 `pg_monitor` / `pg_read_all_stats`）；权限不足时相关模块标记为不可用，而非报错中断。

## AI 工具接口开放

共 8 个，能力如下：

1. **枚举可用实例** —— 列出已配置的数据库实例，并给出后续调用所需的匿名引用，避免暴露真实连接信息。
2. **综合诊断** —— 一次拿到实例当前的关键事实，并在需要时与前一个等长窗口对比，给出基于规则的观察结论（不是健康分）。
3. **指标时间序列** —— 按指定指标和时间窗口取数，一次最多 8 个指标、5 至 120 分钟，可选择与上一窗口对比。
4. **会话查询** —— 按类别取会话：活跃、等待、长查询、长事务、长时间空闲事务，可设时长下限。
5. **阻塞链查询** —— 返回当前的阻塞关系：谁挡住谁、锁对象、以及被阻塞方的 SQL（已脱敏）。
6. **Top SQL 查询** —— 按总耗时、平均耗时、调用次数、返回行数四种口径排序取前 N 条。
7. **复制状态查询** —— 主库 / 备库身份、下游复制连接、复制槽占用与延迟。
8. **执行计划预估** —— 对给定只读语句生成执行计划，**不执行**、不做 ANALYZE，返回计划树。


## 开发与构建

### 环境要求

- Node.js 22.19.0 或更高版本。
- Go 1.24.x。
- npm。依赖版本以仓库中的 `package-lock.json` 为准。
- 构建目标为 Windows x64 和 Linux x64；其他操作系统或 CPU 架构暂不支持运行核心程序。

首次拉取代码后安装依赖：

```powershell
npm.cmd ci
```

执行完整验证。该命令依次运行 TypeScript 类型检查、Go 测试、`go vet`，并构建宿主代码和两个平台的核心程序：

```powershell
npm.cmd run verify
```

只执行某一项检查时可以使用：

```powershell
npm.cmd run check
npm.cmd test
npm.cmd run build
```

### 生成安装包

先完成构建，再通过 npm 生成 tgz：

```powershell
npm.cmd run verify
npm.cmd pack
```

生成的 `hgdb-monitor-<版本号>.tgz` 包含 Harness 宿主代码、浏览器端代码以及 Windows/Linux x64 核心程序，可交给 Harness 的本地插件安装流程使用。`lib/`、`core/bin/` 和 tgz 都是构建产物，不提交到 Git。

### 数据库集成测试

普通 `npm.cmd test` 不要求本地存在 PostgreSQL；未提供连接信息时，数据库集成测试会自动跳过。需要执行真实数据库集成测试时，可在当前终端临时设置以下变量：

```powershell
$env:HGDB_TEST_HOST = '192.0.2.10'
$env:HGDB_TEST_PORT = '5432'
$env:HGDB_TEST_DATABASE = 'postgres'
$env:HGDB_TEST_USER = 'monitor'
$env:HGDB_TEST_PASSWORD = '<test-password>'
npm.cmd test
```

不要将真实账号、密码或连接地址写入源码、README、测试文件或提交记录。
