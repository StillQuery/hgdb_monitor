# hgdb_monitor

`hgdb_monitor` 是一个面向 **HGDB / PostgreSQL** 的只读监控插件。

旨在提供一套轻便的监控系统。它将数据库当下的状态和最近两小时的变化摊开，同时允许 AI 能在对话里查到同样的信息，即定位“现在谁在阻塞”“刚才是不是变慢了”这类问题时，不用切出 Harness。

## 功能

监控能力分五层，从上往下依次收窄：

**① 实例层 · 实时总览**
主备角色、连接使用（总会话 / 活跃 / 等待 / 阻塞 / 空闲事务）、事务速率、缓存命中率、复制延迟、未授予锁、最大连接数。

**② 会话层 · 谁在干什么**
活跃会话、等待会话、长查询、长事务、长时间空闲事务，以及**阻塞链**——谁挡住了谁、锁在什么对象上、被阻塞方的 SQL 长什么样。

**③ SQL 层 · 慢在哪**
Top SQL 排行，可按总耗时、平均耗时、调用次数、返回行数四种口径排序；以及 EXPLAIN 执行计划预估——**只生成计划、不执行语句**。

**④ 复制层 · 下游跟得上吗**
主备身份、下游复制连接、复制槽占用与延迟。

**⑤ 时间层 · 最近两小时怎么变的**
开启持续采集后每 15 秒采样一次，保留最近 2 小时并画出趋势曲线；诊断时可以把当前窗口与**前一个等长窗口**对比，回答“比之前慢了吗”。

## 使用流程

### 1. 进入数据源管理

打开 **HG monitor** 后，点击监控总览右上角的「管理数据源」。首次使用时列表为空，点击页面右上角的「添加数据源」开始配置。插件最多可保存 5 个数据源。

### 2. 填写连接信息

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| 名称 | 页面中用于识别实例的显示名称，不影响数据库连接 | 无 |
| 主机 | HGDB / PostgreSQL 所在主机名或 IP 地址 | 无 |
| 端口 | 数据库监听端口 | `5432` |
| 数据库 | 监控账号要连接的数据库名 | `postgres` |
| 用户名 | 建议使用专门的只读监控账号 | `postgres` |
| 密码 | 新建时必填；编辑时留空表示保留原密码 | 无 |
| SSL 模式 | 支持 `disable`、`allow`、`prefer`、`require` | `disable` |
| 连接超时 | 建立数据库连接的最长等待时间，范围 1～30 秒 | 5 秒 |
| 查询超时 | 单次监控查询的最长执行时间，范围 1～30 秒 | 10 秒 |

填写完成后点击「保存」。保存只会加入数据源列表，不会自动开启持续采集；页面仍停留在数据源管理中，方便继续测试和调整配置。

### 3. 测试连接

在数据源卡片上点击「测试连接」。插件会检查：

- 网络、端口、账号和密码是否可用；
- 数据库版本是否满足要求；
- 当前账号能否读取会话、锁、WAL、复制状态等监控信息；
- 实例是否启用了 `pg_stat_statements`，从而决定能否显示 Top SQL。

测试成功后，数据源会显示「连接已验证」及各项能力标记。权限不足不会影响其他可用模块，但对应模块会显示为不可用。测试失败时，根据页面提示修改主机、端口、账号、密码、SSL 模式或超时设置后重新测试。

### 4. 开启持续采集

实时总览无需开启持续采集即可使用。若需要查看趋势图和进行时间窗口对比，请在已通过连接测试的数据源上打开「持续采集」开关。

- 后台每 15 秒采集一次快照；
- 本地最多保留最近 2 小时数据；
- 刚开启时需要至少两个样本才能形成趋势图；
- 关闭持续采集后停止写入新样本，实时监控仍可继续使用。

### 5. 查看和切换实例

点击左上角「监控总览」返回驾驶舱。实例标题左侧的半齿轮只用于在已有数据源之间循环切换：

- 向上或向下拖动齿轮；
- 点击齿轮的上半区或下半区；
- 齿轮获得焦点后，按键盘上、下方向键。

需要新增、编辑或删除数据源时，请始终从右上角「管理数据源」进入。未通过连接测试的实例可在总览标题下直接点击「测试连接」。

切换实例后，页面会加载该实例的实时指标、会话与阻塞、Top SQL、复制状态及历史趋势。部分数据需要相应权限、扩展或持续采集支持，条件不满足时页面会显示具体提示。

### 6. 日常管理与 AI 查询

在「管理数据源」页面可以完成以下操作：

- **编辑**：修改连接信息；密码留空时不会覆盖已保存的密码；
- **测试连接**：重新验证连接和监控能力；
- **持续采集**：开启或暂停两小时趋势数据采集；
- **删除**：删除数据源及其本地历史监控数据，此操作需要二次确认。

配置完成后，也可以在 AI 对话中直接提问，例如：

- “当前有哪些数据库实例？”
- “生产库现在是否存在阻塞？”
- “最近 30 分钟连接数和事务速率有什么变化？”
- “按总耗时列出 Top SQL。”
- “帮我分析这条只读 SQL 的执行计划。”

助手会根据问题调用对应的监控工具。涉及具体实例时，建议使用数据源的显示名称，便于快速定位。

## 使用限制

- **仅支持 HGDB 及 PostgreSQL 14+ 的PG系数据库**。
- **最多 5 个数据源**；单次明细查询（会话、阻塞、Top SQL、下游连接）最多返回 20 条。
- **历史趋势需要手动开启持续采集**，最长保留 2 小时，超出部分自动丢弃；未开启时只能看实时快照。
- **Top SQL 依赖 `pg_stat_statements` 扩展**，实例未启用该扩展时该模块为空。
- **需要足够的只读权限**（如 `pg_monitor` / `pg_read_all_stats`）；权限不足时相关模块标记为不可用，而非报错中断。

## AI 工具接口开放

共 8 个，能力如下：

1. **枚举可用实例** —— 列出已配置的数据库实例，并给出后续调用所需的匿名引用，避免暴露真实连接信息。
2. **综合诊断** —— 一次拿到实例当前的关键事实，并在需要时与前一个等长窗口对比，给出基于规则的观察结论（不是健康分）。
3. **指标时间序列** —— 按指定指标和时间窗口取数，一次最多 8 个指标、5 至 120 分钟，可选择与上一窗口对比。
4. **会话查询** —— 按类别取会话：活跃、等待、长查询、长事务、长时间空闲事务，可设时长下限。
5. **阻塞链查询** —— 返回当前的阻塞关系：谁挡住谁、锁对象、以及被阻塞方的 SQL（已脱敏）。
6. **Top SQL 查询** —— 按总耗时、平均耗时、调用次数、返回行数四种口径排序取前 N 条。
7. **复制状态查询** —— 主库 / 备库身份、下游复制连接、复制槽占用与延迟。
8. **执行计划预估** —— 对给定只读语句生成执行计划，**不执行**、不做 ANALYZE，返回计划树。


## 开发与构建

### 环境要求

- Node.js 22.19.0 或更高版本。
- Go 1.24.x。
- npm。依赖版本以仓库中的 `package-lock.json` 为准。
- 构建目标为 Windows x64 和 Linux x64；其他操作系统或 CPU 架构暂不支持运行核心程序。

首次拉取代码后安装依赖：

```powershell
npm.cmd ci
```

执行完整验证。该命令依次运行 TypeScript 类型检查、Go 测试、`go vet`，并构建宿主代码和两个平台的核心程序：

```powershell
npm.cmd run verify
```

只执行某一项检查时可以使用：

```powershell
npm.cmd run check
npm.cmd test
npm.cmd run build
```

### 生成安装包

先完成构建，再通过 npm 生成 tgz：

```powershell
npm.cmd run verify
npm.cmd pack
```

生成的 `hgdb-monitor-<版本号>.tgz` 包含 Harness 宿主代码、浏览器端代码以及 Windows/Linux x64 核心程序，可交给 Harness 的本地插件安装流程使用。

### 数据库集成测试

普通 `npm.cmd test` 不要求本地存在 PostgreSQL；未提供连接信息时，数据库集成测试会自动跳过。需要执行真实数据库集成测试时，可在当前终端临时设置以下变量：

```powershell
$env:HGDB_TEST_HOST = '192.0.2.10'
$env:HGDB_TEST_PORT = '5432'
$env:HGDB_TEST_DATABASE = 'postgres'
$env:HGDB_TEST_USER = 'monitor'
$env:HGDB_TEST_PASSWORD = '<test-password>'
npm.cmd test
```
